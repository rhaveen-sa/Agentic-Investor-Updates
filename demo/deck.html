The problem

It's the 31st. The update is due.

  • You open a blank doc at eleven at night.
  • You scroll Slack, Stripe, GitHub and your own calendar, rebuilding a month you already lived.
  • You remember the wins faster than the churn.
  • Investors get it three days late, and they cannot check a single number in it.
Writing the update takes an hour. Remembering the month is the hard part.
[Ask founders at the event when they wrote their last update and how long it took. Put the real answer here, or delete this line.]
The insight

Detail decays. The update gets written at the worst possible moment.

What you can recall is perfect on the day and mostly gone four weeks later, which is exactly when you sit down to write.

So the report is not reporting. It is reconstruction from memory, and memory flatters.

The fix is not a better writer in week four. It is capturing in week one.
The product

An agent that works all month, so month end is only an approval.

Optional · the ledger

A fact has to earn its way into the update.

  • Proposed. The agent reads a source and writes a candidate fact. It never invents a number.
  • Pending. It waits in the feed for the founder.
  • Confirmed. Only these are visible to the report writer.
  • Dismissed. Kept on record, and never reaches the report.

Optional · what is real

What runs, and what is a fixture.

Real

The Claude agent loop and all ten tools, strict JSON schemas, the facts ledger, the report writer, the verifier pass, the approval gate on outbound messages, and the whole interface. Tools execute locally and deterministically. The KPI table is computed from the ledger in code, never written by the model.

Mocked

The five connectors read timestamped JSON instead of live APIs, and a simulated clock moves a week per click, so a month of founder life fits into ninety seconds. Teammate replies arrive from a button rather than Slack.

Every connector already implements one interface, so a real one drops in:

abstract class SourceConnector {
  String get id;
  Future<List<SourceItem>> fetch(
    DateTime since, DateTime until);
}

Optional · the business

Why it gets used every month instead of once.

PULL

The deadline is someone else's

Investors ask for the update whether or not the founder feels like writing. The habit already exists, so we attach to it instead of creating one.

MOAT

The ledger compounds

Every confirmed fact makes the next month's draft better and cheaper to check. Month twelve beats month one, and none of it transfers to a competitor.

WEDGE

Sources travel

The same verified ledger answers a data room request, a board pack and a diligence questionnaire. The monthly update is only the first document.

Start at the monthly update. End as the record of everything a founder has to prove.
